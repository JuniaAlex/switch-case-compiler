# Screenshot Index

All images in `screenshots/` are generated by `scripts/make_screenshots.py`. The script starts the local Python bridge, captures the real frontend with Playwright and Chrome, and renders terminal-style images with PIL.

| File | Caption | What it demonstrates |
| --- | --- | --- |
| `01_valid_ast.png` | Valid join in the compiler frontend | Editor, AST view, validity badge, token count |
| `02_tokens.png` | Token table from the native Flex scanner | Token type, lexeme, line, column |
| `03_semantic_error.png` | Ambiguous column | `S004` diagnostics with source positions |
| `04_syntax_error.png` | Missing closing parenthesis | `P001` and syntax stage |
| `05_lexical_error.png` | Unterminated string literal | `L002` and lexical stage |
| `06_schema.png` | Demo catalog view | Four tables and column types |
| `07_test_results.png` | Compiler and bridge test results | 79/79 cases and 8/8 integration tests |
| `08_json_output.png` | Native `--json` output | Stable contract consumed by the bridge |

## Suggested Use

- Report: use the architecture diagram, test results, valid AST, token table, and one diagnostic screenshot.
- Presentation: use `01_valid_ast.png`, `02_tokens.png`, `07_test_results.png`, and `08_json_output.png`.
- Viva/demo: open `02_tokens.png`, `03_semantic_error.png`, and `06_schema.png` to explain tokenization, name resolution, and catalog checks.

## Regeneration

```powershell
python scripts\make_architecture_diagram.py
python scripts\make_screenshots.py
```

The screenshot script expects:

- Google Chrome at `C:\Program Files\Google\Chrome\Application\chrome.exe`
- Python packages `Pillow` and `playwright`
- A built compiler at `compiler/bin/sqlc.exe`

The browser screenshots are captured from `http://127.0.0.1:8767/` with the Python bridge running; the frontend is never opened through `file://`.
